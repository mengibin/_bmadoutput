## Follow-up Resolutions

### R1 - stale embedding vectors are now detected and rebuilt when the global embedding config drifts

**Resolved behavior**  
- Project KB manifest now records an embedding config fingerprint alongside provider/model metadata.  
- `Knowledge` status marks embedding as not ready when the persisted vectors do not match the current global embedding configuration.  
- Retrieval-side backfill now rebuilds not only missing vectors, but also stale vectors generated by an older embedding config.

**Evidence**  
- `crewagent-runtime/electron/services/projectKbService.ts`
- `crewagent-runtime/electron/services/projectKbService.test.ts`

**Verification**  
- Added regression coverage for “config changes after existing vectors were already built”, and the test now proves retrieval returns `hybrid` after stale vectors are rebuilt.

### R2 - `originalPath` is no longer exposed through the project knowledge status payload sent to renderer

**Resolved behavior**  
- RuntimeStore now has a renderer-safe Project KB status payload that strips `originalPath`.  
- `kb:project:getStatus` and import/rebuild status responses now use that sanitized payload.  
- Renderer-side `ProjectKnowledgeSourceRecord` no longer contains `originalPath`.

**Evidence**

- `crewagent-runtime/electron/electron-env.d.ts`
- `crewagent-runtime/src/stores/appStore.ts`

**Verification**  
- Existing Project KB status assertions now verify renderer-facing status records do not expose `originalPath`.
